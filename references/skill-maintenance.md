## 单一正文与兼容入口

本轮 Windows 安装约定：`C:/Users/A1165/.agents/skills/learning-notes` 是本地维护源，`.codex/skills/learning-notes` 通过目录联接访问同一份文件。目录联接只解决本机两个路径共用文件，不要求包内嵌套同名目录。2026-10-24 起本地维护源本身是 `https://github.com/Babel36acl/learning-notes` 的克隆（分支 `main`）：改后先隔离验证再 commit/push，他机用 `npx skills add <仓库地址>` 或 `git clone/pull` 同步。更新前核实实际路径和联接；其他机器确认自己的维护源，不复制 Windows 联接到跨平台分发包。

OpenViking 的 `viking://user/chuixin/skills/learning-notes` 是跨宿主分发目标。更改可能来自任一宿主：更新前读取并比较完整包，发现独有内容就先合并，不凭日期覆盖。上面的本地维护源不授权忽略远端新改动。它不是自动双向同步；修改后需显式分发并读回。

本技能的安装树和分发包只保留根部一个 `SKILL.md`，递归清点时按文件名计数，不以 frontmatter 是否存在判断会不会被发现。支持文件不得再叫 `SKILL.md`；不依赖某个宿主恰好忽略 references 或隐藏目录。包内文件使用明确清单，根部之外的兼容副本、备份和历史版本放到技能扫描根之外。

旧 `embedded-learning-notes` 是不同调用名的外部入口，思源参考也只是普通支持文件，可继续指向当前规则。退役嵌套路径前检查实际调用方，迁移可确认的引用并保留可恢复备份；不能为了保留一个过渡路径而继续分发第二个同名技能。2026-10-19.3 已将旧嵌套 12 文件移出本地安装树；其他宿主安装时仍需检查并清理自己的旧残留，不能只把新包覆盖上去。

## 更新与分发

1. 读取当前入口、受影响参考和分发目标，记录可恢复基线。按实际行为把规则放在一处，入口只增加必要路由；保留既有用户内容。
2. 核对 frontmatter、相对链接和默认调用提示；对安装树和解包结果递归枚举所有 `SKILL.md`，本包应恰好一个，同时比较整个文件清单。借助可用的 skill 校验器检查格式，格式通过不能代表宿主发现或加载通过。
3. 从 [行为验收场景](validation-scenarios.md) 选覆盖改动的任务，在隔离目录验证可观察行为。脚本或工具变更另测其真实效果；不靠关键词存在宣称模型会遵守。
4. 再核对目标基线，保存授权范围内的改动。分发 OpenViking 时使用技能安装入口更新完整包，不能只更新主文件而遗漏参考，也不能通过普通资源写入绕开安装。相同内容且清单相同时无需重复上传。其覆盖安装会保留新包省略的旧文件；需要退役旧文件时，先完整备份、核对范围并准备可安装包，再用官方技能移除/安装机制处理，不能仅省略文件后宣称已清理。
5. 逐文件读回；服务可能正规化 YAML 和换行，应比较解析后的元数据与正文，不能掩盖实质差异。分别记录文件一致、检索发现、宿主重新加载和行为验证，未执行的层次明确保留。

发布提交、公开仓库上传、自动定时同步均需处于明确任务范围。一次更新不自动建立这些动作。

## 扩展能力的判据

先判断现有参考是否足以承接新任务。检索问答、冲突/时效核验、复盘和讨论回流由现有路由处理；只有独立触发需求明显且内容足够不同才拆新技能。

写入幂等、原子版本检查、引用解析和可恢复事务属于执行工具能力。文字要求不能冒充已经实现的拦截器。后续出现实际失败时，先修拥有该状态的工具或局部规则，再选择验证场景，不把一次故障升级为每篇笔记的永久流程。

2026-10-19.4 在 [笔记工具](note-tools.md) 提供静态只读影响预览与经 Obsidian API 的受保护保存、操作回执和按页恢复。其范围与限制以该入口及实际执行证据为准。分发时包含 scripts 全部依赖文件和测试入口；运行产生的计划、原文备份、请求和回执保留在包外，不上传用户笔记。
