# Obsidian 搜索、写入与验证

库路径以当前用户指定和实际检查为准，核实根目录及 `.obsidian`。历史路径与上轮活动窗口不决定本轮目标。用户明确指定的临时测试目录可以不含 `.obsidian`，不能因此改用真实库。

文件工具可完成基本读写。Obsidian CLI 是可选入口，使用前确认当前命令位置、版本和帮助；需要客户端的能力还要检查客户端可用。不把过去机器上的检查写成本次通过。

## 选用入口

已具备本地库访问时，可直接读取和编辑 Markdown，无需思源 MCP。普通搜索先用 `rg` 定向查题目和旧页；写入保持 UTF-8 和原有换行。保存前读实际文件、保留未知 frontmatter 和用户内容；批量修改先保存原件与目标清单，写前检查原文件未被并发改变。

客户端和 CLI 可用时先确认实际目标库，配合精确的库内相对路径，避免同名文件或默认活动文件导致误写。以下 PowerShell 仅说明参数数组的形式；变量来自本次实际环境，命令顺序须先查当前帮助：

```powershell
& $obsidianCommand help read
$noteReadArgs = @("vault=$vaultName", 'read', "path=$noteRelativePath")
& $obsidianCommand @noteReadArgs
```

上述读取目标只是示例，先核对文件存在；不要照抄示例创建文件。用参数数组传递含空格、中文或多行的内容，避免跨 shell 拼接。CLI 或已授权连接器不可用时，可以完成文件级写入并如实报告，不能把另一入口用于绕过明确权限拒绝。

## 读取范围与结果

按 [问题检索](knowledge-inquiry.md) 定位材料。搜索片段只证明片段，不能代替全文；识别分页、截断和读取失败。完整总结或整体改写前补齐对象；定点编辑可只读足以理解及保护周边的范围，并使用保留其余字节的局部修改工具。工具不支持这种保留时先完整读取。

结果按实际情况说明：`empty` 是成功查询无结果，`unavailable` 是入口不可达，`unsupported` 是能力未提供，`failed` 是明确失败，`cancelled` 是取消，`truncated` 是内容未返回完。写操作另分 `completed`、`partial`、`noop` 与 `write_uncertain`；调用取消或失败仍可能已经产生写入，要按实际读回判断。它们与事实可信度、来源可用性不是同一状态。

## 保存与恢复

需要改名/合并影响预览、版本保护保存或局部恢复时，使用 [实际工具入口](note-tools.md)。已有 Markdown 的受保护修改通过 Obsidian `Vault.process` 核对旧版本；工具不可用时不能把普通文件写入说成同等级保护。只读预览不自动执行结构改动，也不是每次短记的必经步骤。

写前核对精确目标与当前内容。已有文件须有可恢复原文，已验证覆盖当前版本的历史也可满足；哈希用于识别版本，不能代替原文。新建页确认目标仍不存在。保留编码、换行、未知属性及人工内容；批量操作另存目标清单和必要映射，备份放库外或约定位置。

提交前比较当前内容与阅读基线。发生并发修改时重读并重做最小差异，保留用户新改动；没有原子条件写入能力时，这种前置检查只能缩小竞争窗口，不能声称完全防并发。

超时、中断或结果不明时先读回目标：目标效果已经出现就不重做；确认未发生时才安全重试；仍不能确认则停止该写入并说明未知。恢复任务先检查上次实际状态，不盲目重放全部操作。批量部分完成按目标记录已完成、未完成和不明项，按依赖续做。

恢复只撤回本次可确定的差异，不全库覆盖回退。待恢复文件又被用户修改时先比较并保留新增内容。同步不能替代可恢复历史。

## 读回什么

核对保存内容及预期差异；新建页检查入口链接、实际目标文件、标题和块 ID，附件检查实际路径。客户端可用时检查 `metadataCache` 的 frontmatter、链接目标与 unresolvedLinks；引用存在不等于标题存在，需继续检查目标标题/块。只检查受影响页面并与修改前对照，历史坏链单独记录。有意未建页的概念链接单独识别，不以 unresolvedLinks 数量清零为目标，也不把线索伪称为现有页。

对排版、Properties、Bases 或 Canvas 的修改，在阅读视图检查实际结果；可使用当次帮助确认的 `dev:screenshot` 及截图查看。没有客户端时保留具体未验项目。不要把同步到 NAS/手机、其他 AI 重新发现技能或渲染可读性由磁盘写入推定为已通过。

## 恢复与授权

只读检查和请求范围内的可逆修改按现有授权完成。删除、覆盖其他内容、批量迁移、发布及外部消息仍须在任务范围。保留批量改动原件、前后哈希和路径映射；备份优先放到库外，避免进入搜索与反链。改名/移动先核实旧文件、目标冲突和反向引用，优先由客户端更新链接，随后重新读回。

合并和改名还要检查标题/块锚点、别名显示文字、嵌入、附件及外部引用；客户端已更新链接也要核对受影响内容。无论选哪种工具，都必须具备对应引用更新与验证能力，不能用批量替换同名词代替路径映射。

清理时检查实际用途与恢复路径；孤立、未解析、长期未打开不是删除理由，附件还可能被非 Markdown 内容或外部使用。`publish: true` 只是文件意图，发布仍要核对用户授权、目的地和公开范围。

必要的中断交接放正文外：任务范围、已完成目标、剩余目标、使用的来源/目标版本、当前未知写入及下一步。接手模型先核对现状；普通一次保存不强制另建交接报告。
